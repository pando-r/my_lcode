调研任务：为 lcode（一个 Python 写的终端 AI 编程助手）寻找 GitHub 上可直接复用的「图片 / 文件 / 视频识别」能力代码，并产出一份可执行的接入报告。

## 背景：lcode 的架构落点
- src/lcode/tool/           工具层，每个工具是 Tool 子类，注册进 Registry 后由 Agent 调用
- src/lcode/mcp_servers/    内置 MCP server，通过 .lcode.yaml 的 mcp_servers 段挂载
- src/lcode/llm/            模型接入层（OpenAI 兼容协议）
报告里的接入建议必须落到这三个具体位置之一，不要泛泛而谈。

## 调研方法（按顺序尝试，记录实际用了哪条）
1. 用 bash 调 GitHub REST API 搜索（未认证 60 次/小时，控制在 10 次调用内）：
   curl -s "https://api.github.com/search/repositories?q=<关键词>&sort=stars&per_page=10"
   建议关键词：vision-language-model agent、multimodal OCR、video understanding、image captioning CLI、minicpm-v、moondream、qwen2.5-vl、ollama vision、whisper、paddleocr、markitdown
2. 读候选仓库 README 补充细节：
   curl -s "https://raw.githubusercontent.com/<owner>/<repo>/main/README.md"
   （main 取不到就试 master）
3. 如果 curl 不可用或被限流，改用 mcp__web__search_web，并在报告开头注明「数据来源受限，部分字段未核实」。

## 报告内容要求
从结果中筛出 5-8 个候选，逐个给出：
- 仓库地址、star 数、主要语言、License（GPL/AGPL 要标为高风险）
- 能力：图片理解 / OCR / 视频抽帧理解 / 通用文件解析，各自支持到什么程度
- 接入方式：pip 包、HTTP 服务、还是必须本地跑模型；需要 GPU 吗；模型体积多大
- 接到 lcode 的具体落点：新增 tool/ 工具 还是 新增 mcp_servers/ server，并说明理由
- 风险与代价：许可证、离线可用性、延迟、每千次调用成本

最后给出 2-3 条推荐路线并做取舍，例如：
- 路线 A：先做 OCR + 图片描述（低成本、立刻可用）
- 路线 B：接本地小 VLM（moondream / MiniCPM-V，离线但吃显存）
- 路线 C：接云端多模态 API（效果最好、按量计费）

## 硬性约束
- 只做调研。不要安装任何依赖，不要 git clone 大仓库，不要修改项目源码。
- 允许写文件，但只能写在项目目录内。允许执行命令，危险命令会被黑名单拦截。
- 不要为了凑内容编造 star 数或 License；拿不到的字段写「未获取」。

## 产出
1. 完整报告写入 docs/vision-capability-research.md（中文 Markdown，候选对比用表格）。
2. 最终回答给出 300 字以内摘要 + 你推荐的那一条路线 + 下一步该改哪个文件。
